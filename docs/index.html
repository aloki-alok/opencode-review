What it does

Every time someone opens or updates a pull request, OpenCode reads the change, follows it through your repo, and leaves one short comment with the defects the change introduces. A second pass tries to prove each finding wrong before you see it. The comment is edited on every push, never duplicated.

Here is a real one:

Changes needed: 1 thing. :/

1. add() subtracts instead of adds (app/calc.py:2). Restore return a + b

OpenCode review of 48d310a98, advisory. Reply if a finding is wrong.

  • Read-only. The model can read your code and nothing else: no edits, no shell, no web.
  • Your runner, your model. Any model OpenCode supports. OpenRouter by default. No service to sign up for, nothing stored anywhere.
  • Short. At most 5 findings, under 150 words, no praise and no style nits.
  • Free and open source. MIT licensed. You only pay your model provider.

Set it up in two steps NEW!

1. Add your model key as a secret. In your repo: Settings, Secrets and variables, Actions, New repository secret. Name it OPENROUTER_API_KEY. Get a key at openrouter.ai/keys.

2. Add this file as .github/workflows/opencode-review.yml:

name: OpenCode review

on:
  pull_request:
    types: [opened, synchronize, reopened, ready_for_review]
  issue_comment:
    types: [created]
  pull_request_review_comment:
    types: [created]

permissions: {}

concurrency:
  group: >-
    opencode-review-${{ github.event_name == 'pull_request'
    && format('pr-{0}', github.event.pull_request.number)
    || format('comment-{0}', github.event.comment.id) }}
  cancel-in-progress: ${{ github.event_name == 'pull_request' }}

jobs:
  opencode:
    if: github.event_name == 'pull_request' || startsWith(github.event.comment.body, '/oc')
    runs-on: ubuntu-latest
    timeout-minutes: 10
    permissions:
      contents: read
      pull-requests: write
      issues: write
    steps:
      - uses: aloki-alok/opencode-review@v0
        with:
          model: openrouter/deepseek/deepseek-v4.1-flash
          api-key: ${{ secrets.OPENROUTER_API_KEY }}

That's it. Open a pull request and a review appears in a few minutes. :D

Two things to know:

  • /oc commands start working once this file is on your default branch. GitHub runs comment triggers from there only.
  • If your organization limits which actions may run, allow aloki-alok/opencode-review@*.

Want it smarter about your repo? Copy templates/guide.md to .github/opencode-review/guide.md and write a few lines about what the project is and the rules that matter. The reviewer reads it first. It also reads your AGENTS.md, both from the base branch, so a pull request can't rewrite the rules for its own review.

Ask questions with /oc

Comment on any issue or pull request:

CommentDoes
/oc why does this retry twice?Answers in the thread with file:line references. On a pull request it reads the PR's code and diff.
/oc reviewRuns the review again and updates the review comment.

Only repo owners, members and collaborators can use commands. Bots and pull requests from forks are ignored.

How it works

  1. The action fetches the pull request's head, its base and their merge base, and builds the diff. Lockfiles, translations and minified files are left out.
  2. Find pass: OpenCode reads the diff, follows callers and types through the repo, and lists the defects it can back with a concrete scenario.
  3. Refute pass: a second OpenCode run tries to prove each finding wrong. Only the ones that survive are posted.
  4. The comment is written and edited in place. The job summary shows times, turns and the model.

Time is sized to the change: 90 seconds up to 20 changed code lines, and 240 for anything bigger. If a pass runs out of time, OpenCode is stopped and asked for what it found so far, so work is not thrown away. A new push cancels the review of the old commit.

Reading the comment

Starts withMeans
Changes needed: 2 things. :/Defects found and double-checked. Each names the file, the line and a fix.
Nothing blocking found. :)The review finished and found nothing worth blocking on.
... Stopped at the time limitIt ran out of time but kept what it found.
Review did not finish ... -_-Out of time with nothing to show. Comment /oc review to retry.
Review failed for ... :(Something is set up wrong, like a dead API key. The reason says what.

Security

  • The model only reads. Every OpenCode tool is denied except read, glob, grep and list. Reads outside the checkout are denied, and so are symlinks that lead out of it.
  • The pull request can't change the reviewer. The action's code and prompts come from its pinned version. The PR's opencode.json and .opencode/ folder are removed before OpenCode starts.
  • Secrets stay out of reach. OpenCode gets only the model key. The GitHub token is never in its environment and never written to disk. Logs mask the key.
  • Only members trigger it. Bot comments, drafts, Dependabot and fork pull requests are skipped, and so is a pull request that changes no code.
  • Prompt injection can at worst produce a misleading comment, because the model can't act. Treat the review as advice, never as an approval gate.

FAQ

Does it cost anything?

The action is free and MIT licensed. You pay your model provider for the tokens each review uses, and GitHub for runner minutes if your plan charges for them.

Can the AI change my code or approve my pull request?

No. The model can only read files. It has no edit, shell or web tools, and the action only posts comments. It never approves or blocks a merge.

Which models does it support?

Any model OpenCode supports, set as provider/model. OpenRouter is the default, and Anthropic, OpenAI, Google and others work with their own key.

Does it work on pull requests from forks?

No. Fork pull requests are skipped so your model key never reaches code from outside your team.

Can I run it on a self-hosted runner?

Yes, for private repos. The runner needs python3 3.11 or later, git and npm. Give reviews their own label so they don't wait behind builds. On a public repo the action refuses to run on a self-hosted runner unless you opt in.

How do I know a prompt or model change made it better?

The repo ships a bench that replays real bug-introducing pull requests several times each and reports the catch rate, false alarms, timing and the spread between runs. 17 public cases from httpx, click and flask are included.
